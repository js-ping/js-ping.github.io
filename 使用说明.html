使用说明

线上地址：https://uppjs.com

这份说明写给完全不想碰命令行的人。从头到尾，你只需要会两件事：改文件、双击一个图标。

一、30 秒了解这个网站

这是一个纯静态的个人清单站，一共四个页面：

页面网址内容是什么改哪个文件
首页uppjs.com导航：软件清单入口 + 各页面入口不用改，自动生成
软件清单uppjs.com/apps.html软件、硬件、外设README.md
网址书签uppjs.com/links.html常用网站和在线工具links.md
使用说明uppjs.com/help.html就是本文使用说明.md

四个页面长一个样：顶上是搜索框，左边是目录，右上角能换配色。搜索是全站通用的——打几个字，四个页面里的内容都能立刻查出来。

一句话原理：你写 markdown 文件 → 双击一个图标 → 脚本把 markdown 编译成网页 → 自动传到网上。
网页文件（.html）永远不要手改，每次都会被覆盖。

二、日常只有两个动作

动作 1：改内容

双击 1-编辑内容.command → 自动用 VSCode 打开 README.md。

步骤做什么
1双击 1-编辑内容.command
2在编辑器里改内容：加一条、改说明、调分类
3想看效果：光标放正文里，按 Cmd + K 松开，再按 V，右侧弹出实时预览
4按 Cmd + S 保存。不保存等于没改
5关掉 VSCode，去双击 2-更新网站.command

想改「网址书签」页，用同一个图标打开，把文件从 README.md 换成 links.md 就行（在 VSCode 左侧文件列表里点一下即可）。

为什么是 VSCode： 改 Markdown 最顺手——有语法高亮、有实时预览、Cmd + F 找东西、Cmd + Z 一路撤销。项目里还配好了设置：长行自动换行、中文标点不会被误报成"可疑字符"，打开就能用。

说到底，内容源就是个纯文本文件，用哪个编辑器都行。
只有一条禁忌：别用 Word / Pages 这类富文本编辑器打开，它们会往里塞格式代码，把文件搞坏。

动作 2：更新上线

双击 2-更新网站.command，剩下的全自动：

步骤自动做什么
①编译四个页面，并告诉你共多少个分类、多少条
②把改动提交到 git
③推送到 GitHub
④打开本地预览，弹窗告诉你结果

看到「✓ 完成」就成了，大约 1 分钟后线上更新。

网络不通怎么办？ 推送可能失败，但改动已经安全存在本地，一个字都不会丢。等网络好了重新双击 2-更新网站.command 即可。

三、内容怎么写（这一节最要紧）

打开 README.md，满屏 markdown。别怕，真正会用到的写法只有四种：

写法长什么样页面上是什么
大分类## Mac 软件一级分类，出现在左侧目录里
小分组- 装机必备：（冒号结尾）可折叠的分组标题
一条条目- [名称](网址)：一句话说明一个条目，能点开链接
补充一行再缩进一级的 - 小字说明挂在条目下面的小字

就这四种，没有别的规则。

一条条目怎么拆

- [IINA](https://iina.io/)：Mac 上最好用的免费播放器｜就是启动稍慢
  └─ 名称 ─┘ └── 网址 ──┘ └──── 说明 ────┘ └─ 个人点评 ─┘
部分必须吗说明
名称必须中括号里的字，页面上显示的名字
网址不必须圆括号里。不写也行，只显示名字，一样能搜到
说明不必须冒号后面第一段，跟名字同一行显示
个人点评不必须用全角竖线 ｜ 隔开的第二段，单独一行、灰色小字
补充小字不必须再缩进一级写，挂在条目下面

页面上所有数字（目录里的条数、页脚的总数）都是脚本自己数出来的，你不用管。

💡 点评是这个清单最值钱的部分。 网上软件介绍到处都是，但"文件一多就卡""盗版太多，还在找笔中"这种话只有你能写。这是区别于软件测评号的地方，值得每条都补一句。

想干什么，就怎么写

想干什么怎么写
加一条软件复制一整行 - [名字](网址)：说明，改掉内容
加一个分组写 - 分组名：，下面缩进写条目
只记个名字，没有网址- 小米巨能写。 直接写，不加括号
一条挂好几行小字再缩进一级继续写 - 小字
标一个"推荐"名称前加 ☆，页面上会出现一个「荐」徽章
标记一个已弃用用 ~~删除线~~ 包起来，页面上变灰并加删除线
想写给自己看的备注用 <!-- 备注 -->，网页上完全不出现

换个说法也能认，但建议统一

脚本对下面这些写法全都认，但混着用页面会看起来不齐整，建议统一成一种：

你可能会写推荐写成
- 名字，一句话说明- 名字：一句话说明
- [名字](网址),说明- [名字](网址)：说明
- 名字 。 说明- 名字：说明
名称里塞 （6.25 版本） （开源）照写没问题，会原样留在名称里

记住一句话：名称和说明之间，用中文冒号 ： 隔开。

顺带一提，说明末尾要不要加句号都行——加了脚本会自动去掉，页面上更齐整。

四个最容易踩的坑

坑会怎样怎么避免
用 Tab 键缩进层级会乱只用空格，一层 2 个或 4 个都行，但要一致
只写 - 分组名：，下面没有缩进内容页面上就是一行孤零零的字分组下面至少放一条缩进的条目
一个井号 # 标题只认两个井号 ##，一个井号会被当普通文字分类一律用 ##
一条里塞两个链接第二个会跑进说明里拆成两条最清楚

加一条软件的完整例子

## Mac 软件

- 装机必备：
    - [IINA](https://iina.io/)：万能的视频播放器，免费开源。
        - 支持几乎所有格式，不用额外装解码器。
    - ☆ [Rectangle](https://rectangleapp.com/)：免费的窗口管理，快捷键顺手。
- 工具类：
    - [Mounty](https://mounty.app/)：让 Mac 能写入 NTFS 格式的 U 盘。

保存后双击 2-更新网站.command，一分钟后就出现在网上。

「网址书签」页怎么写

links.md 的写法和 README 一模一样，只是分类和条目换成了网站。想加一个常用网站，找到对应分类（比如 ## 在线工具），在下面加一行：

- [PDF24](https://tools.pdf24.org/zh/)：在线处理 PDF，免费全能，不用装软件。

书签页排版更紧凑，所以说明写得越短越好，一句话说清是干什么用的就行。写完同一个脚本一起编译，不用额外操作。

四、文件都是干什么的

日常你只会碰最上面两行，其余全是自动生成的，不要手动改：

文件作用你要动它吗
README.md软件清单的内容源✅ 常改
links.md网址书签的内容源✅ 常改
使用说明.md本文的内容源🔘 偶尔改
index.html / apps.html / links.html三个网页，自动生成❌ 手改会被覆盖
使用说明.html / help.html说明书的网页版，同一份内容两个名字❌ 自动生成
build.py编译脚本🔘 加新页面、改配色才动
1-编辑内容.command双击 → 打开内容源🔘 双击用
2-更新网站.command双击 → 编译 + 上线🔘 双击用
favicon.* / icon-*.png网站图标不用动
manifest.webmanifest手机加到主屏的配置，自动生成不用动
robots.txt / sitemap.xml给搜索引擎看的，自动生成不用动
edgeone.json托管平台的构建配置❌ 不要删
docs/两份进阶文档（备案、升级路线）想看时再看
唯一要记住的规则：只改那三个 .md 文件。
手改 .html 下次更新会被覆盖，白改。

说明书为什么有三个名字

文件什么时候用
使用说明.md在 VSCode 里读和改（这是内容源）
使用说明.html双击直接在浏览器看，排版好
help.html和上面那份内容完全一样，只是名字短，方便在手机上输网址（uppjs.com/help.html）

你只维护 md 那一份，两份 html 在每次更新时自动生成，永远不会不同步。

五、页面上的按钮都是干什么的

右上角「外观」

点开是一个小面板，四个选项：

选项作用
明暗自动 / 浅色 / 深色。选「自动」就跟系统走
底色8 种预设底色，点一下就换
自定义…弹系统取色器，自己挑任意颜色
恢复默认一键回到出厂配色

选完底色后，文字颜色会自动适配（浅底自动用深字，深底自动用浅字），不用担心看不清。实测标题对比度 ≥12:1、正文 ≥4.9:1，都在无障碍标准线以上。

设置只存在你自己这台浏览器里。换设备、换浏览器都是默认配色，也不影响别人，更不上传任何东西。

想加一种底色或改预设色： 打开 build.py 搜 presets，会看到一个数组，一行一个颜色：

{name: '暖阳', bg: '#f7efd9'},

name 是鼠标悬停时显示的名字，bg 是底色。加一行多一个色块，删一行少一个（面板一行排 4 个，建议保持 4 的倍数最整齐）。

顶栏的其他东西

元素作用

筛选项「有下载链接的」只看能直接点开的；「我推荐的」只看标了 ☆ 的

搜索的几个小细节

  • 搜索时所有分组自动展开，命中的留下，没命中的自动收起。
  • 分组标题右边的数字变成 「命中数 / 总数」，一眼看出这一类里命中几条。
  • 大小写无所谓，中文英文都能搜。
  • 试试搜这几个词感受一下：截图、下载、pdf、heic。

六、想在手机上看 / 加到主屏

方式怎么做
手机浏览器看直接输 uppjs.com，四个页面都能点

八、首次在 macOS 上运行的安全提示

.command 文件本质是可执行脚本，macOS 第一次会拦下来：

现象处理
提示「无法打开，因为来自身份不明的开发者」右键点文件 → 打开 → 在弹窗里再点「打开」。只需做一次
提示「已损坏，无法打开」打开「终端」，输入 xattr -cr （末尾有个空格），把整个文件夹拖进去，回车

为什么会有这个提示？ 因为这两个脚本没有苹果签名。它们做的事很简单：一个调 VSCode 打开文件，一个跑 build.py 然后 git push。你可以右键 →「显示包内容」，用文本编辑器打开检查，不用担心。

如果双击后终端窗口一闪就没了，说明执行出错。可以在终端里手动跑一次，看详细信息：

cd ~/IdeaProjects/js-ping.github.io && ./2-更新网站.command

十、数据安全与免责

关于隐私，这个网站的做法：

  • 纯静态页面：没有后端、没有数据库、没有统计脚本、不请求任何第三方 CDN。
  • 不收集任何访问数据，不埋点，不上报。
  • 本地存储只有一项：你的外观偏好，存在你自己的浏览器里，不会上传。
  • 页面上的链接指向第三方站点，点过去之后的行为不受本站控制。

免责声明：

  • 清单是个人使用记录，链接来自公开网络，不保证长期有效，也不提供任何软件下载托管。
  • 软件版权归各自厂商所有。清单里出现"破解""激活"等字样只代表记录，不代表推荐，请通过正规渠道购买授权。
  • 按本说明操作造成的任何后果，由操作者自行承担。

想干什么看哪份

加一个新页面的完整步骤（想试的时候再看）：

  1. 新建一个内容源，比如 books.md，写法跟 README.md 一样。
  2. 打开 build.py，在 LIST_PAGES 里加一条：
dict(src="books.md", out="books.html", kicker="看过的书",
     title="书单", sub="带一句短评。", layout="list"),
  1. 双击 2-更新网站.command。页面、搜索、目录、配色、导航全都自动有，不用再写一行代码。
  2. 想让它出现在首页，再去 OTHER_PAGES 里加一行。

layout 有两个值："list" 是普通清单（软件页那种），"compact" 是紧凑排布（书签页那种）。
