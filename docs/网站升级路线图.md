# 网站升级路线图

> 回答三个问题：这套网站还能干什么？软件站还能加什么？能不能做动态网站？
> 面向 uppjs.com · 更新日期：2026-10-01

---

## 一、这套网站还能干什么

先说最关键的一个事实：

> **这套基建和"软件"没有绑定。**
> `README.md → build.py → index.html` 这条流水线，换成任何一份内容源，就是一个新站点。

而且 `build.py` 可以编译**任意多份**清单文件，产出多个页面。比如 `books.md → books.html`、`articles.md → articles.html`。
**加一个页面的边际成本几乎为零**——同一套模板、同一套搜索、同一套配色，复制一份内容源就行。

### 可以直接做出来的站

| 站 | 内容源 | 折腾程度 | 说明 |
|---|---|---|---|
| 个人主页 / 名片页 | `profile.md` | 低 | 现在首页已经有点像了，加个"关于我"就完整 |
| 书单 / 影单 / 播客清单 | `books.md` | 低 | 你 Obsidian 里有素材，直接搬 |
| 公众号文章归档页 | `articles.md` | 低 | **比在公众号里翻历史消息清楚得多** |
| 网址书签站 | `bookmarks.md` | 低 | 浏览器书签导出一转就行 |
| 作品案例集 | `works.md` | 低 | 你写的 Python 小程序、脚本工具 |
| AI 工具导航 | `ai.md` | 中 | 建议**独立成站**，跟主站分开 |
| 一建备考资料索引 | `yijian.md` | 中 | 公式表、口诀、错题本、进度 |
| 给孩子学习页 | `kids.md` | 中 | 古诗、英语语法对照（你正在研究文言文↔英语语法） |
| 笔记站 | `notes.md` | 中高 | 「不落北风」565 篇得先筛非私密部分 |
| 价格观察页 | `deals.md` | 低但需勤更 | 降价/羊毛，时效性强 |

### 这对你意味着什么

你是效率/AI 工具博主，一鱼五吃。**这套基建就是你的"内容矩阵底座"**：

- 每期视频上线 → 网站加一条
- 每篇小红书笔记 → 网站加一条
- 每篇公众号文章 → 网站加一条

三个实在的好处：

1. **平台会限流、会封号，网站不会**——这是你自己的地
2. 一个统一入口，比在五个平台各翻一遍强
3. 能被搜索引擎收录，多一条流量来源

这件事**不花钱**，只是把已经做好的内容多贴一份。

> **一个提醒**：站多了之后要有聚合入口。最简单的做法是首页顶部加一排"站内导航"链接，别让几个站各自孤立。

## 二、软件站本身还能加什么

### A. 内容层面（按重要性排）

| # | 加什么 | 为什么重要 |
|---|---|---|
| 1 | **AI 工具类目** | ★ 你是 AI 工具博主，站里这块**完全空白**，是最大的硬伤 |
| 2 | **「最后验证日期」** | 清单类内容最大的敌人是过期。每条标个日期，读者才知道这行还新鲜 |
| 3 | **一句话结论前置** | "值不值得装"放在最前面，别让人读三行才明白你的态度 |
| 4 | **替代方案** | "A 不好用可以换 B"——这是清单区别于搜索结果的**核心价值** |
| 5 | **平台标签** | Win / macOS / iOS / Android / 网页，一眼筛 |
| 6 | **免费付费 + 开闭源 + 国内可用** | 三组标签，读者最关心的三件事 |
| 7 | **使用场景** | "我用它做什么"——正好是你的差异化铁律：**不做测评，做实践者** |
| 8 | **踩坑记录** | 装之前的坑、卸载残留、有没有广告。这是别人抄不走的东西 |

> 你已经有了「名称 / 简述 / 点评」三分法。上面的 3、4、8 就是把「点评」这块做厚，**它才是你区别于测评号的地方**。

### B. 功能层面（纯前端就能做，零成本零风险）

| 功能 | 说明 | 难度 |
|---|---|---|
| **PWA** | 加到手机主屏、离线可用 | 低 ★ 强烈推荐 |
| 收藏夹 | 访客自己标星，存自己浏览器里 | 低 |
| 「已装 / 想装」标记 | 让访客从"看"变成"用" | 低 |
| 排序 | 按名称 / 分类 / 最近添加 | 低 |
| 单条分享链接 | 生成带锚点的链接，直接发人 | 低 |
| 导出 | 把当前筛选结果导成 Markdown / CSV | 低 |
| 拼音搜索 | 输 `jietu` 也能找到「截图」 | 中 |
| 分组展开状态记忆 | 记住上次哪些分组开着 | 低 |
| 深浅 + 配色调整 | ✅ **已完成**（8 种底色 + 自定义取色器） | — |
| 对比模式 | 选两个工具并排看 | 中 |

### C. 不建议做的

| 别做 | 原因 |
|---|---|
| 评论系统 | 需要后端；个人站容易变成垃圾场，还招骂 |
| 用户投稿 | 同上，且要承担内容合规责任 |
| 花哨动画 | 你自己定的调子是"实用为主，不必太美" |

## 三、能不能做动态网站？

**能。而且不用买服务器。**

先把"动态"这件事拆开——它其实是三层，很多人把它们混在一起了。

### 第 1 层：纯静态（你现在在这）

内容写死在 HTML 里，改内容要重新构建、重新推送。

- 成本 0，速度最快，最安全，没有可被攻击的面
- 缺点：更新要走"改内容 → 构建 → 推送"这个流程

### 第 2 层：静态外壳 + 浏览器端数据

页面还是静态的，但**访客自己的数据**存在他自己的浏览器里（localStorage / IndexedDB）。

- 收藏、标记、笔记、阅读进度、浏览历史、外观偏好——全在这一层
- **不联网、不需要后端、不需要备案、零成本**
- 关键判断：**你想要的大部分"动态功能"，其实属于这一层**

### 第 3 层：真动态（需要服务端）

数据要存在服务器上、多用户共享、需要登录。2026 年这类需求**依然不用买服务器**：

| 方案 | 用途 | 成本 |
|---|---|---|
| EdgeOne Pages Functions | 边缘函数，写 JS 就跑 | 免费额度 |
| EdgeOne KV | 键值存储 | 免费额度 |
| 云数据库（Supabase 一类） | 关系型数据、用户、权限 | 有免费额度 |
| 第三方 API | 直接调别人现成的服务 | 看具体服务 |

### 什么需求落在哪一层

| 你想要的功能 | 需要后端吗 | 怎么做 |
|---|---|---|
| 访客收藏、标记、进度 | ❌ 不需要 | localStorage |
| 搜索、筛选、排序、对比 | ❌ 不需要 | 纯 JS |
| 计算器、生成器、格式化工具 | ❌ 不需要 | 纯 JS |
| 深浅色、配色调整 | ❌ 不需要 | localStorage ✅ 已完成 |
| 离线可用 | ❌ 不需要 | PWA（Service Worker） |
| **留言 / 评论** | ✅ 需要 | EdgeOne Functions + KV |
| **用户投稿** | ✅ 需要 | 同上 |
| **多用户共享数据 / 排行榜** | ✅ 需要 | 云数据库 |
| **登录注册** | ✅ 需要 | 云服务认证 |

### 一句话结论

> **你现在的站，绝大多数"动态需求"在第 2 层就能满足——零成本、零风险、不用备案、不用服务器。**
> 等真的要做评论、投稿、登录了，再上 EdgeOne Functions。**到那时候依然不用买服务器。**

### 顺带澄清一个常见误解

**备案和"动态/静态"毫无关系。** 备案只跟一件事有关：**你是否使用中国大陆的加速节点**。
做了动态功能不备案，照样能跑，只是慢。

## 四、建议的动作顺序

按性价比排（投入产出比从高到低）：

| # | 做什么 | 为什么是现在 |
|---|---|---|
| 1 | 补 **AI 工具类目** | 你是 AI 工具博主，站里没这块说不过去 |
| 2 | 每条加 **「最后验证日期」** | 清单类内容的信任基础 |
| 3 | 加 **PWA**（手机主屏 + 离线可用） | 一次配置长期收益，单文件静态站天然适合 |
| 4 | **收藏夹 + 已装标记** | 让访客从"看"变成"用"，会回来第二次 |
| 5 | **一句话结论 + 替代方案** | 内容质量的分水岭 |
| 6 | **拼音搜索** | 中文站搜索体验的关键一环 |
| 7 | **导出功能** | 让清单能被搬走 = 传播 |
| 8 | 第二个内容源（书单 / 文章归档） | 复用全套基建，边际成本极低 |
| 9 | 备案 | 等有推广需求时再做，见《备案操作手册》 |

## 五、如果只做一件事

**把 AI 工具类目补起来。**

理由很直接：你的定位是 AI 工具博主，网站是你的"作品集"。一个 AI 工具博主自己的网站上，AI 工具那一栏是空的——这是最容易被看出来、也最容易补上的一个洞。

其余的都可以慢慢来。清单类内容的价值不在功能多，在**"我试过、我还在用、我知道坑在哪"**。
