## 一、这套网站还能干什么

先说最关键的一个事实：

> **这套基建和"软件"没有绑定。**
> `markdown → build.py → 网页` 这条流水线，换成任何一份内容源，就是一个新页面。

而且这件事**已经落地了**：现在一次编译产出四个页面——首页 `index.html`、软件清单 `apps.html`、网址书签 `links.html`、使用说明 `help.html`。
**加一个页面的边际成本几乎为零**——同一套模板、同一套搜索、同一套配色，往 `build.py` 的 `LIST_PAGES` 里加一条就行。

|---|---|---|---|
| 个人主页 / 名片页 | `index.html` | ✅ 已完成 | 首页就是导航页，想加"关于我"随时加 |
| 网址书签站 | `links.md` | ✅ 已完成 | 552 条，11 个分类 |
| 书单 / 影单 / 播客清单 | `books.md` | 低 | 你 Obsidian 里有素材，直接搬 |

### 这对你意味着什么

你是效率/AI 工具博主，一鱼五吃。**这套基建就是你的"内容矩阵底座"**：

- 每期视频上线 → 网站加一条
- 每篇小红书笔记 → 网站加一条
- 每篇公众号文章 → 网站加一条

三个实在的好处：

1. **平台会限流、会封号，网站不会**——这是你自己的地
2. 一个统一入口，比在五个平台各翻一遍强
3. 能被搜索引擎收录，多一条流量来源

这件事**不花钱**，只是把已经做好的内容多贴一份。

> **一个提醒**：站多了之后要有聚合入口。最简单的做法是首页顶部加一排"站内导航"链接，别让几个站各自孤立。

## 三、能不能做动态网站？

**能。而且不用买服务器。**

先把"动态"这件事拆开——它其实是三层，很多人把它们混在一起了。

### 第 1 层：纯静态（你现在在这）

内容写死在 HTML 里，改内容要重新构建、重新推送。

- 成本 0，速度最快，最安全，没有可被攻击的面
- 缺点：更新要走"改内容 → 构建 → 推送"这个流程

### 第 2 层：静态外壳 + 浏览器端数据

页面还是静态的，但**访客自己的数据**存在他自己的浏览器里（localStorage / IndexedDB）。

- 收藏、标记、笔记、阅读进度、浏览历史、外观偏好——全在这一层
- **不联网、不需要后端、不需要备案、零成本**
- 关键判断：**你想要的大部分"动态功能"，其实属于这一层**

### 第 3 层：真动态（需要服务端）

数据要存在服务器上、多用户共享、需要登录。2026 年这类需求**依然不用买服务器**：

| 方案 | 用途 | 成本 |
|---|---|---|
| EdgeOne Pages Functions | 边缘函数，写 JS 就跑 | 免费额度 |
| EdgeOne KV | 键值存储 | 免费额度 |
| 云数据库（Supabase 一类） | 关系型数据、用户、权限 | 有免费额度 |
| 第三方 API | 直接调别人现成的服务 | 看具体服务 |

### 什么需求落在哪一层

| 你想要的功能 | 需要后端吗 | 怎么做 |
|---|---|---|
| 访客收藏、标记、进度 | ❌ 不需要 | localStorage |
| 搜索、筛选、排序、对比 | ❌ 不需要 | 纯 JS |
| 计算器、生成器、格式化工具 | ❌ 不需要 | 纯 JS |
| 深浅色、配色调整 | ❌ 不需要 | localStorage ✅ 已完成 |
| 离线可用 | ❌ 不需要 | PWA（Service Worker） |
| **留言 / 评论** | ✅ 需要 | EdgeOne Functions + KV |
| **用户投稿** | ✅ 需要 | 同上 |
| **多用户共享数据 / 排行榜** | ✅ 需要 | 云数据库 |
| **登录注册** | ✅ 需要 | 云服务认证 |

### 一句话结论

> **你现在的站，绝大多数"动态需求"在第 2 层就能满足——零成本、零风险、不用备案、不用服务器。**
> 等真的要做评论、投稿、登录了，再上 EdgeOne Functions。**到那时候依然不用买服务器。**

### 顺带澄清一个常见误解

**备案和"动态/静态"毫无关系。** 备案只跟一件事有关：**你是否使用中国大陆的加速节点**。
做了动态功能不备案，照样能跑，只是慢。

## 四、建议的动作顺序

按性价比排（投入产出比从高到低）：

| # | 做什么 | 状态 | 说明 |
|---|---|---|---|
| 1 | 补 **AI 工具类目** | ✅ 已补 | 现在 `## AI 工具` 有 15 条 |
| 2 | **PWA**（加到手机主屏） | ✅ 已做 | 一次配置长期收益，单文件静态站天然适合 |
| 3 | **第二个内容源**（网址书签） | ✅ 已做 | 复用全套基建，边际成本几乎为零 |
| 4 | **导航首页** | ✅ 已做 | 首页只做入口，软件清单顶在最显眼的位置 |
| 5 | **一句话结论 + 替代方案** | 待做 | 内容质量的分水岭，比加功能重要 |

## 五、如果只做一件事

**把「一句话结论 + 替代方案」补起来。**

清单类内容的价值不在功能多，在**"我试过、我还在用、我知道坑在哪"**。
网上软件介绍到处都是，但"文件一多就卡""A 不好用可以换 B"这种话只有作者能写——这是这份清单区别于软件测评号的地方。

目前的写法支持到：

```markdown
- [IINA](https://iina.io/)：Mac 上最好用的免费播放器｜就是启动稍慢
                                                        ↑ 这一小段就是差异化
```

配套的「替代方案」可以写成条目下面的补充小字：

```markdown
- [PDF24](https://tools.pdf24.org/zh/)：在线处理 PDF，全能免安装。
    - 要客户端就用 PDFgear，功能互补。
```

其余的都可以慢慢来。
